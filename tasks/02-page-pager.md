# 02. Page, I/O, Cache, And Pager

目標：按 production 依賴先搬入 allocator、completion、`IOResult`、VFS/file trait、SQLite header/page、buffer pool、page cache 與 `Pager`。Target 保留原相對路徑；不得先寫同步 pager 再於第 08 章「改成 async」，因為 Turso production 從一開始就是 completion + `IOResult` + resumable state machine。

本章共同背景：`learn/06a-file-format-pages.md`, `learn/06a-source-code-learn-file-format-pages.md`, `learn/07b-ioresult-reentry.md`, `docs/agent-guides/async-io-model.md`。`Pager` 對 WAL/B-tree 的 production reference 可以暫時尚未形成完整 crate closure，但只能保留原 reference，不能以 stub 或 alternate implementation 填洞；可執行的 storage closure 在 T670 驗證。
